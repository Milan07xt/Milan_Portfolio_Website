AI Portfolio Assistant

Intelligent, Context-Aware Portfolio Assistant Using FastAPI & Generative AI

Python / FastAPI
Generative AI
Full Stack
2025

Problem Statement

As a fresher developer building a portfolio website, I faced a critical challenge: how to make my portfolio more engaging and interactive without requiring visitors to manually browse through dozens of projects, certificates, and experience details?

Key Challenges:

  • Low Engagement: Static portfolio pages don't capture visitor attention or encourage questions
  • Information Overload: Too much content scattered across different sections makes it hard for recruiters to find what they need
  • Lack of Personalization: A generic portfolio doesn't showcase problem-solving skills or tech depth
  • Manual Updates: Any portfolio change would require updating both the website AND the AI backend
  • AI Hallucination Risk: Using AI without proper grounding could lead to false information about projects or credentials

I decided to build an AI Portfolio Assistant — an intelligent chatbot that understands my portfolio context and answers visitor questions dynamically, accurately, and professionally.

Solution Approach

Instead of a generic AI chatbot, I designed a context-aware system that grounds responses in structured portfolio data. The architecture uses three interconnected layers:

1. Frontend Widget Layer

A modern, floating chat widget injected directly into the portfolio HTML. It provides:

  • Responsive chat interface with message history
  • Smooth animations and dark/light theme support
  • Seamless integration without obstructing content
  • Real-time streaming responses from the backend

2. FastAPI Backend Layer

A lightweight Python microservice exposing a /chat REST endpoint that:

  • Accepts user queries and manages conversation context
  • Uses function calling (OpenAI Tools) to access portfolio data safely
  • Prevents hallucination by only using data from structured JSON files
  • Returns formatted, professional responses

3. Knowledge Base Layer

Structured JSON files storing all portfolio information:

  • profile.json — Bio, role, location, status
  • projects.json — Project details, tech stack, links
  • skills.json — Technical skills with proficiency levels
  • certificates.json — Certifications and achievements
  • experience.json — Professional experience and internships
  • education.json — Academic background
  • contact.json — Contact information

Key Design Decision: Instead of RAG (Retrieval-Augmented Generation) with expensive embeddings, I used OpenAI Function Calling to allow the AI to "request" specific portfolio data on-demand. This approach is:

  • ✅ Cost-effective (no vector database needed)
  • ✅ Fast (minimal API calls)
  • ✅ Accurate (only uses verified data)
  • ✅ Easy to maintain (update JSON files, not the AI)

Technical Implementation

Architecture Overview

The system follows a modular, event-driven architecture:

User Question (Frontend) ↓ FastAPI /chat Endpoint ↓ OpenAI Function Calling Agent ↓ Tool Router (Reads from JSON) ↓ Formatted Response (Backend) ↓ Streamed to Frontend Chat Widget

Key Implementation Details

1. Function Calling Schema

Defined tool schemas to guide the AI in accessing portfolio data safely:

Tools Available: ├── get_profile() → Bio, role, contact status ├── get_skills() → Technical skills & proficiency ├── get_projects() → All projects with descriptions ├── get_certificates()→ Certifications list ├── get_experience() → Work experience & internships ├── get_education() → Academic background └── get_resume() → Resume download link

2. System Prompt Design

Crafted a robust system prompt that enforces constraints:

  • ✓ Only answer questions about Milan's portfolio
  • ✓ Never invent or hallucinate information
  • ✓ Provide links and resources when available
  • ✓ Redirect off-topic questions gracefully
  • ✓ Use professional but friendly tone

3. Frontend Integration

The widget communicates with the backend via:

fetch('https://your-api.com/chat', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ message: userInput }) })

4. Error Handling & Fallbacks

  • Missing API keys detected at startup
  • Graceful fallbacks for missing data files
  • Network error recovery in frontend
  • User-friendly error messages

Challenges & Solutions

Challenge 1: Preventing AI Hallucination

Problem: GPT could generate fake projects, make-up certifications, or invent skills.
Solution:
  • Implemented Function Calling instead of RAG — the AI must explicitly request data via tools
  • Only loads data from verified JSON files, not from internet searches
  • System prompt strictly forbids hallucination with clear consequences
  • Tested with adversarial prompts like "Tell me about a fake project at Google"

Challenge 2: Handling Multiple AI Models

Problem: API key errors, model unavailability, or quota limits from a single provider.
Solution:
  • Implemented model fallback strategy — primary model with 5+ fallback options
  • Graceful error handling when API keys are missing
  • Support for both OpenAI (GPT-4) and Gemini API with the same interface
  • Environment variable configuration for easy switching

Challenge 3: Maintaining Portfolio Sync

Problem: Portfolio website and AI backend need to stay in sync; manual updates are error-prone.
Solution:
  • Used single source of truth approach — AI reads the same JSON files as documentation suggests
  • Frontend and AI both reference centralized portfolio data
  • Clear documentation: "To add a project: edit `projects.json`"
  • Modular architecture ready for RAG/vector DB migration without API changes

Challenge 4: CORS & Deployment

Problem: Frontend running on Vercel, backend on Railway — CORS errors and environment setup complexity.
Solution:
  • Enabled CORS in FastAPI with proper headers
  • Documented deployment steps for Railway, Render, and Heroku
  • Used environment variables for API keys and URLs
  • Created `.env.example` template for easy onboarding

Challenge 5: Response Quality & Formatting

Problem: AI responses could be verbose, poorly formatted, or lack relevant links.
Solution:
  • Instructed AI to use markdown formatting (bold, bullet points, links)
  • Prompt engineering to keep responses concise yet informative
  • Tool responses include URLs for projects, GitHub repos, LinkedIn, etc.
  • Testing with real visitor questions to refine response quality

Conclusion

The AI Portfolio Assistant demonstrates full-stack engineering skills: backend architecture (FastAPI), AI/ML integration (function calling), frontend development (JavaScript widget), and DevOps (deployment pipelines).

By choosing function calling over RAG, I built a system that is faster, cheaper, and more reliable than typical AI implementations. The modular architecture ensures that adding new portfolio content requires only JSON edits, not code changes.

Most importantly, it actually works — zero hallucinations, accurate responses, and a delightful user experience. This project showcases not just coding ability, but the judgment to choose pragmatic solutions over trendy ones.

💡 Key Takeaway: Sometimes the best solution isn't the most complex one. By using simple, well-designed JSON files with function calling, I built a production-grade AI system that outperforms many over-engineered alternatives.
